# ما تحتاجه الواجهة من الخادم

هذا المستند يلخّص ما أضافته الواجهة الأمامية (`listen.html` و `broadcast.html`) وما تفترض وجوده في الخادم ولم يُنفَّذ بعد.

---

## 1. الاتصال الحالي (موجود في فجر)

| النقطة | الملف | الوصف |
|--------|-------|-------|
| `POST /transcribe` | transcribe.py | ملف صوتي + `target_language` → `{original_text, translation}` |
| `POST /translate` | translate.py | `{text, target_language}` → `{translation}` |
| `WebSocket /ws/{room_id}` | rooms.py | ترحيل نصي بين العملاء المتصلين |

---

## 2. ما تحتاجه الواجهة إضافةً

### 2.1 عدد المستمعين عبر WebSocket

**الحاجة:** تعرض `broadcast.html` عدد المستمعين في الوقت الحقيقي.

**المطلوب:** عند انضمام عميل أو مغادرته، يُرسَل الخادم رسالة JSON لجميع العملاء في الغرفة:
```json
{ "type": "listeners", "count": 5 }
```

---

### 2.2 رسائل حالة الجلسة

**الحاجة:** تعرف `listen.html` متى يبدأ البث ومتى ينتهي لتنتقل بين الشاشات تلقائياً.

**المطلوب:** يُرسَل الخادم (أو يُمرَّر من المذيع عبر WS) رسالتين:
```json
{ "type": "started" }
{ "type": "ended" }
```
> ملاحظة: الواجهة الحالية ترسلهما من المذيع مباشرةً عبر WS. إن أراد فجر التحقق من الهوية يمكن أن يُضيف middleware يفلتر هذه الرسائل.

---

### 2.3 كشف الآيات من الخادم

**الحاجة:** ترسل `broadcast.html` النص العربي للخادم وتتوقع رجوع بيانات الآية (`sura`, `ayah`) إن وُجدت، لإعادة بثها للمستمعين ضمن حقل `verse` في رسالة الـ segment.

**المطلوب:** نقطة HTTP جديدة تلف `verses.match_verse`:
```
POST /detect_verse
Body:  { "text": "النص العربي" }
Returns: { "sura": 2, "ayah": 255, "score": 94 }
     أو: null
```

> الملف `verses.py` موجود في الجذر وجاهز للاستيراد. يكفي تغليفه بـ FastAPI route.

---

### 2.4 ترجمة كل اللغات دفعةً واحدة

**الحاجة:** تستدعي `broadcast.html` `/translate` مرتين (ur وhi) بعد كل مقطع، مما يُضاعف الطلبات.

**المطلوب (اختياري):** نقطة تُرجع الترجمات الثلاث في طلب واحد:
```
POST /transcribe_all
Body: multipart: file + (no target_language)
Returns:
{
  "original_text": "...",
  "en": "...",
  "ur": "...",
  "hi": "..."
}
```
> إن لم تُنفَّذ، تواصل الواجهة عمل ثلاثة طلبات منفصلة (كما هي الآن).

---

### 2.5 التحقق من رمز الغرفة

**الحاجة:** تُدخل `broadcast.html` رمز الجامع قبل البث. حالياً لا يوجد تحقق — أي رمز يُقبَل.

**المطلوب (اختياري):** نقطة خفيفة:
```
GET /room/{room_id}/exists
Returns: { "valid": true|false }
```
> إن لم تُنفَّذ، تبقى التجربة مقبولة — سيُنشَئ الاتصال فور فتح WS.

---

## 3. تنسيق رسالة الـ Segment الموصى به

ترسله `broadcast.html` للمستمعين عبر WebSocket بعد كل مقطع صوتي:

```json
{
  "type":       "segment",
  "ar":         "النص العربي المُتعرَّف عليه",
  "en":         "The recognized Arabic text",
  "ur":         "پہچانا گیا عربی متن",
  "hi":         "पहचाना गया अरबी पाठ",
  "is_hadith":  false,
  "is_unclear": false,
  "verse": {
    "sura":      2,
    "ayah":      255,
    "score":     94,
    "sura_name": "البقرة"
  },
  "ts": 1727987654321
}
```

> حقل `verse` يكون `null` إن لم تُكتشَف آية. حقل `is_unclear` يُعيَّن `true` حين يكون النص فارغاً أو قصيراً.

---

## 4. ملاحظات للتنفيذ

- الواجهة تدعم `webm` و `mp4` — تأكد من أن `/transcribe` يقبل كلا الصيغتين.
- رسائل WS المُرسَلة من المذيع قد تصل قبل اكتمال الترجمة؛ لا مشكلة — المستمع يعرضها فور وصولها.
- CORS: الواجهة تعمل من ملف HTML محلي أو خادم ثابت؛ تأكد أن FastAPI يسمح بـ `*` أو بالأصل المناسب.
